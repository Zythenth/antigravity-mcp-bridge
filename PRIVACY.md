# Privacy and storage

This policy describes the data handled by Black Gravity (formerly Antigravity MCP Bridge). The bridge is an independent local program; it does not operate a data collection service.

## Data used

The MCP client provides the prompt, the working directory, and the task options. The bridge selects files according to Git ignore rules and `includePaths`, creates a temporary copy, and hands the prompt to the official `agy` CLI. The CLI can read the copy and communicate its content to Google services according to the chosen model, account, and settings. See the [Google privacy policy](https://policies.google.com/privacy) and the terms that apply to your Antigravity account. See also the [official Antigravity CLI installation guide](https://www.antigravity.google/docs/cli/install/).

The bridge does not access the CLI's authentication stores or log in on behalf of the user. Official authentication is performed by `agy` itself through native credential managers (Windows Credential Manager, macOS Keychain, or Linux Secret Service via D-Bus). The bridge preserves profile and configuration directories, security session, D-Bus, proxy, certificates, `GEMINI_API_KEY`, and `GOOGLE_GEMINI_BASE_URL`. ADC and Enterprise variables (`GOOGLE_APPLICATION_CREDENTIALS`, `GOOGLE_CLOUD_PROJECT`, `GCLOUD_PROJECT`, `GOOGLE_CLOUD_UNIVERSE_DOMAIN`) are preserved in the environment for compatibility; the Enterprise flow has not been validated end to end.

Before copying project files, the bridge runs a preventive secret preflight AFTER applying Git exclusions and selection through `includePaths`, and BEFORE making the temporary copy. The preflight blocks `.env`, `.env.local`, and other `.env.*` variants (except `.env.example`, `.env.sample`, `.env.template`, and `.env.dist`, which still go through content analysis), `.envrc`, private keys, keystores, known authentication files, and high-confidence credential patterns by content. Certificates, public keys, and synthetic test fixtures remain allowed. Explicit secret exceptions use a strict versioned JSON object format (`{"version": 2, "namePatterns": [...]}`); in version 2, the exception skips only the credential name check (`SECRET_FILE`), keeping the content scan and block (`SECRET_CONTENT`) on all allowed files. The `copy.ready` event reports `blockedFiles` with only the path and reason (`SECRET_FILE`, `SECRET_CONTENT`, `SECRET_EXCLUSION`, `UNSAFE_PATH`), never exposing file content. The preflight does not guarantee detecting arbitrary secrets in code, unknown formats, or encrypted data.

Previews, context, and artifacts reapply the preventive secret policy. Patch preparation binds the staging to the inspected bytes and restores the private index; per-file patch reading (`readProjectPatch`) extracts the slice directly from the reviewed diff without unsafe rereading of the shared index or the working tree; snapshots omit blocked generated files and reject a contaminated baseline. Artifacts verify paths, policy, and integrity before responding. Policy failures report the path and reason, without including the detected content. These checks are limited to the formats recognized by the scanner.

The CLI subprocess receives a filtered environment through `cliEnvironment`, omitting by default third-party service credentials (AWS, GitHub, OpenAI, Stripe) and local agents (`SSH_AUTH_SOCK`, `GPG_AGENT_INFO`). Runtime injection variables and dynamic namespaces (`NODE_OPTIONS`, `NODE_PATH`, `LD_*`, `DYLD_*`) are strictly forbidden from opt-in on any platform, emitting diagnostics that name the variable without ever exposing its value. The bridge does not log environment variable values or pass tokens as arguments. Authentication and communication with Google belong to the CLI. The bridge adds no telemetry, analytics, or transmission to a service of its own.

Local Git operations use their own list of variables, without credentials, proxies, or injection variables. `PATH` is reduced to absolute directories outside the project and the copy. Hooks, fsmonitor, and global execution settings are disabled; the applicable ignore rules are consulted separately. The `agy` environment and authentication keep their specific policy.

## Local data and retention

- The copy and the Git baseline stay in the system temporary directory. They are removed by discard, by eviction of the last retained record, or 7 days after the last finished task, according to `COPY_RETENTION_HOURS`. Cleanup occurs at startup and every minute while the server is active. Copies in use are preserved. The operating system can also delete temporary files. File and byte limits (`MAX_COPY_FILES` and `MAX_COPY_BYTES`) are respected during the scan and the copy; identity, size, or hash changes fail with `SOURCE_CHANGED` or `CONTEXT_CHANGED`, and copy creation does not silently omit baseline files that become credentials.
- `~/.black-gravity`, or `BRIDGE_STATE_DIRECTORY`, stores prompts, criteria, options, task/session IDs, paths, hashes, statuses, results, available events, review citations, and tests reported by the client or captured from the executor. For Windows tests, it includes the normalized global policy, its hash, the effective selection, and cleanup recovery data. Approval mode settings (`BRIDGE_APPROVAL_MODE`, default `auto` if unset, or strict `ask`) live in the server's private startup environment; in `ask` mode, the remember checkbox has been removed and there is no bypass for remembered legacy roots. `StateStore` has no generic support for cloud storage. The default retains up to 100 tasks. This state has no encryption of its own; protect it with operating system permissions and keep it out of shared folders and repositories. The first start without `BRIDGE_STATE_DIRECTORY` copies an existing `~/.antigravity-mcp-bridge` into it and leaves the previous directory in place with the same content. The user deletes the previous directory themselves when it is no longer needed.
- Prompts, messages, and private memory containing high-confidence credential formats (PEM private keys, GitHub tokens, Google keys, live Stripe keys, and values of secret environment variables) are refused with `INPUT_SECRET_DETECTED`, without persisting or sending the text. Old memories with those values are returned redacted and cannot be selected.
- The event buffer is limited. Events and outputs can be truncated. Up to 20 test records are kept per task, with output limited by each test's selection; the default is 4,000 characters.
- CLI frames are copied with a depth limit (64) and a node limit (100,000) and redacted before any event, result, message, or response. Response deltas are released only per complete line, with redaction that tracks private key blocks across lines; incomplete lines above 8 KiB are suppressed with an explicit indication. Test outputs and errors, including native ones, are also redacted. State written by earlier versions is redacted when restored. Redaction covers known formats; it does not detect arbitrary secrets.
- Operational logs on `stderr` include the time, task ID, status, PID, and structured error or termination codes (`AGY_NOT_FOUND`, `AGY_PERMISSION_DENIED`, `AGY_PROBE_FAILED`, `AGY_INCOMPATIBLE`, `CLI_INPUT_FAILED`, `AGY_IO_FAILED`, `AGY_PROCESS_FAILED`, `TASK_CANCELLED`, `TASK_TIMEOUT`). The bridge does not add the prompt to those logs or record credential values. On cancellation or timeout (where the first intent prevails), the bridge triggers termination of the process and descendants, with no perfect guarantee for processes that escape the process group or operating system permissions. Error messages from external tools may contain unknown secrets; the bridge applies redaction to known error forms and patterns and its operations do not add credential values to logs, without promising absolute absence. The MCP client and the CLI may keep their own histories and logs.
- Tests on the legacy path create a temporary runner in the copy and a temporary Git snapshot without the original's history. On Windows, the bridge also temporarily creates the controller, prepared runtime, and AppContainer/LPAC profile. These resources are removed at the end or reconciled during recovery after an interruption. The permission selection and granted paths are not sent to `agy`; an optional fix by `agy` receives only the necessary task context. Outputs and evidence appear in the local records.
- When Git for Windows is prepared for LPAC tests, only PE executables, DLLs, and public helpers are copied to a single-link runtime in read-only mode, without granting ACLs to the original installation or inheriting `.gitconfig`, user credentials, or keys. Git configuration is isolated with `GIT_CONFIG_NOSYSTEM=1`, `GIT_TERMINAL_PROMPT=0`, and a global configuration file absent in the temporary scratch, new temporary repositories use isolated `GIT_DEFAULT_REF_FORMAT=reftable` without converting existing repositories or changing host settings, host settings and credentials are not read/copied, and Git is not downloaded.
- The explicit preparation of the Windows portable runtime queries the GitHub Release to download its declared files. This step does not send project files, prompts, or task data to GitHub. It does not change the normal `agy` flow, which remains subject to the Google account, model, and policies described above. In directories under sync such as OneDrive, tolerance of an extra or transient link count (`nlink`) is restricted exclusively to reading assets with a trusted descriptor and pinned size and SHA-256, to the staging of the portable Node source with `expectedSha256`, and to the portable Node preparation lock (as long as `device`, `inode`, and `size` remain identical and the exact nonce/payload is checked, releasing with `unlink` only the process's own entry to preserve aliases). Hash, size, file identity, reparse marks, and directory layout remain strictly mandatory; runtime destinations, generic executables, and ACL grants still require a single link.
- The private runtime cache is kept for reuse after normal restarts. Persistence after a physical reboot has not yet been verified.

Per-project and per-specialist memory is stored in `project-memory/` inside the private state. Only entries explicitly selected by the caller are sent to the CLI. Tasks retain snapshots of the selected text to allow consistent resumes; listing memories and querying tasks return metadata, and reading text uses a separate tool.

The `group-<UUID>.json` records keep definitions, prompts, owners, dependencies, profile hashes, and references to tasks. They stay in the private state until local removal, with up to 100 groups and 4 MiB per definition. Tracking responses return metadata and limited public messages. Each node uses the copy and task retention rules described above.

## Removal

`black_gravity_discard` removes the copy and the baseline, including resumed tasks that share those directories. It preserves the local task records, results, and events. Local removal does not delete histories kept by Google, the CLI, or the MCP client.

`black_gravity_memory_remove` deletes the current version of an entry given its hash. Snapshots already associated with tasks remain in the respective records, and local removal does not delete content already sent to the CLI or to Google.

To delete persisted records, stop the bridge servers using the state directory and remove the JSON files of the desired tasks, or the entire state directory. This loses the IDs and the ability to recover those sessions through the bridge. Discard the copies before removing the records to avoid leaving temporary directories without a reference.

Before sending a task, check `black_gravity_list_project_files`, select only the necessary paths, and exclude confidential documents and credentials through local Git rules. Do not include secrets in the prompt, in recorded test outputs, or in public problem reports.
