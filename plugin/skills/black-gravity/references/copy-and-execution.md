# Copy and execution details

Reference for the [core skill](../SKILL.md). Open it when dealing with copy contents and limits, line-ending errors, `leftoverFiles`, or `TASK_OWNED_BY_OTHER_SERVER`.

1. Identify the absolute Git root of the project. Before writing the task, read the relevant instructions and files and note existing Git changes. Do not include secrets or private documents in the prompt sent to Antigravity. Use `antigravity_list_project_files` to check what can go into the copy.
2. For a query, review, diagnosis or second opinion, use `mode: "read-only"`; this mode uses `agy --mode plan`, checks for changes at the end and does not allow integration. For implementation, use `mode: "write"` (default). Call `antigravity_run` with a concrete instruction and a verifiable criterion. The host requires Git 2.32 or later for global configuration isolation through `GIT_CONFIG_GLOBAL`. By default, the copy includes tracked and untracked files that are not in `.gitignore`, `.git/info/exclude` or global/XDG ignore rules preserved by the bridge (with safe executable resolution, PATH rebuilt with absolute entries, fsmonitor and hooks disabled and no global execution filters), even when an ignored file is tracked. Select `includePaths` when only some files or folders are needed; the selection cannot include ignored files. When specifying `includePaths`, the prompt written for the delegate MUST list the exact paths of those files and request changes or queries exclusively about them (never say only vague terms such as "selected files" without naming them, which leads the delegate to try to guess names), instruct the delegate to report missing dependencies as unverifiable and to finish the task without widening the scope or attempting refused searches on disk. If you receive `COPY_LIMIT_EXCEEDED`, reduce the selection with `includePaths`. For `CHANGE_LIMIT_EXCEEDED`, review the size of the task with the user; do not try to work around the limit. The defaults are 10,000 files/256 MiB copied and 100 changed files. The bridge requires `agy --sandbox` and always works in the copy.

**Avoiding recurring executor failures**: the bridge appends environment and editing rules to every prompt: the copy does not contain dependencies or build outputs ignored by Git (such as `node_modules`), paths outside the copy are unavailable, denied tools must not be retried and edits must be minimal without duplicating logic, preserving line endings, full signatures, timers and lifecycle. In the delegation prompt, explicitly list the exact paths of `includePaths` and request only those files (never vague terms without naming them), instructing the delegate to report missing dependencies as unverifiable and to finish without refused searches or widening the scope. When the task does not need a terminal, restrict `allowedTools` to the file tools and `finish`; say in the prompt what the coordinator will build and test on the host. Send `antigravity_send_message` through the same MCP connection that started the task (another connection receives `TASK_OWNED_BY_OTHER_SERVER`). In write runs, the executor receives pure CRLF text files as LF, so that exact edit searches do not fail because of line endings; when it finishes, all of them go back to CRLF before the preview (events `copy.line-endings-converted` and `copy.line-endings-restored`), and the unedited ones stay identical to the original. After successful runs, the bridge restores in the edited text files the line-ending format they had before the run, or the majority one when the file is new, and records the `patch.line-endings-normalized` event; a file that was already mixed keeps the ending of each unedited line, and a BOM that the executor removed comes back (event `patch.bom-restored`). Integration never changes line endings or the BOM of the original: a BOM removed by the patch is given back and listed in `restoredByteOrderMarks`; any other change is refused with `LINE_ENDINGS_CHANGED` without touching the original, and then fix the copy (for example, by resuming the task) and generate a new preview. `INTEGRATION_FAILED` indicates a write failure, with the files already written returned to their previous bytes; `leftoverFiles` lists deleted files that were left with a temporary name in the folder and must be deleted by hand. `LINE_ENDINGS_UNRESTORED` indicates that the restoration is waiting for confirmation that the run's processes have ended. When reviewing the patch, reject or fix duplicated blocks, lines rewritten without change, parameters dropped when wrapping functions, unrequested changes to timers, errors or lifecycle, values changed beyond those requested and unrequested new files, such as temporary or scratch files.

`--sandbox` restricts the CLI's terminal commands, but does not guarantee complete file system isolation on Windows. Do not delegate access to sensitive files based only on this option; use the file list and review the content actually copied.
